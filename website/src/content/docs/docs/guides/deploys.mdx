VigilOps can deploy an app that runs with Docker Compose. It pulls the new image, restarts the service, waits for a health check to pass, and rolls back to the previous image if it doesn't.

You can trigger a deploy from Telegram (`/deploy myapp`), from the server (`vigil deploy myapp`), or from CI through a webhook.

<Aside type="caution">Apps are currently registered in VigilOps's source code, so servers running the published image can't add their own apps yet. Until that changes, you need to [build your own image](/docs/contributing/develop/). Registering apps with a command is planned.</Aside>

## Register an app

Add it to [`src/deploy/deploy.config.ts`](https://github.com/VigilOpsHq/vigil/blob/main/src/deploy/deploy.config.ts):

```ts
const deployConfig: Record<string, AppDeployConfig> = {
  'myapp': {
    composePath: '/opt/myapp/docker-compose.yml',
    service: 'app',
    image: 'ghcr.io/me/myapp',
    healthCheckUrl: 'https://myapp.com/health',
    healthCheckTimeout: 60,
    rollbackOnFailure: true,
  },
};
```

| Field | Meaning |
|---|---|
| `composePath` | The app's `docker-compose.yml`. It must be under `/opt`, which is mounted into the VigilOps container |
| `service` | The service name in that compose file |
| `image` | The image to pull |
| `healthCheckUrl` | URL that must answer successfully after the deploy |
| `healthCheckTimeout` | Seconds to wait for the health check |
| `rollbackOnFailure` | Go back to the previous image if the health check fails |

List registered apps with `vigil apps` or `/apps`.

## Deploy from GitHub Actions

<Steps>

1. **Expose the webhook.** It listens on port `3100` (`WEBHOOK_PORT`). Put it behind nginx with HTTPS:

   ```nginx
   server {
       listen 443 ssl;
       server_name vigil.mydomain.com;

       ssl_certificate     /etc/ssl/certs/cert.pem;
       ssl_certificate_key /etc/ssl/private/key.pem;

       location / {
           proxy_pass http://127.0.0.1:3100;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
       }
   }
   ```

2. **Turn on the webhook.** Generate a secret with `openssl rand -hex 32`, add it to `/opt/vigil/.env` as `VIGIL_WEBHOOK_SECRET=...`, and run `vigil stop && vigil start`. Then add the same value as a secret named `VIGIL_WEBHOOK_SECRET` in your app's GitHub repository.

   Without this setting the webhook is off: `/webhook/*` answers `503`, and deploys from Telegram and the CLI still work.

3. **Call the webhook** after your workflow pushes the new image:

   ```yaml
   - name: Deploy with VigilOps
     run: |
       curl -fsS -X POST https://vigil.mydomain.com/webhook/deploy \
         -H "Content-Type: application/json" \
         -H "x-vigil-token: ${{ secrets.VIGIL_WEBHOOK_SECRET }}" \
         -d '{"app": "myapp"}'
   ```

</Steps>

The webhook replies straight away with `{"status":"accepted"}`. The deploy result arrives on Telegram.

## Webhook endpoints

| Method and path | Auth | Purpose |
|---|---|---|
| `GET /health` | None | Returns `{"status":"ok"}` if VigilOps is running |
| `POST /webhook/deploy` | `x-vigil-token` header | Starts a deploy. Body: `{"app": "<name>"}` |
| `GET /webhook/apps` | `x-vigil-token` header | Lists registered apps |
